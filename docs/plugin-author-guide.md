# Plugin author guide

## Submit a plugin

Use the plugin submission Issue template or copy an existing YAML record. A stable record needs:

- a canonical GitHub repository and 40-character pinned commit;
- the exact package/install target, if one exists;
- an SPDX license identifier with source evidence;
- a DSH plugin identity rather than a Skill, MCP server or generic project;
- a factual summary, compatibility statement, permission notes and data-flow evidence;
- a stable 52DSH Chinese detail URL.

Do not submit credentials or install-time secrets. The registry workflow will not install or execute your plugin.

## Claim or update a record

Open the author claim template, identify the registry ID, link evidence showing your maintainer relationship, and list the fields that changed. Maintainers preserve evidence history and may require a new pinned commit before updating a version or verification claim.

## Add a Chinese tutorial

The registry links to tutorials maintained on 52dsh.com so that structured facts and long-form instructions have one source each. Request a tutorial through an Issue; do not paste a duplicate long article into the YAML file.
